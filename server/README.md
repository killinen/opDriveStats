# Engagement Gauge Server

A minimal FastAPI application for serving the engagement statistics generated by `engagement_gauge_dev.py`.

## Features

- Serves aggregated engagement metrics per device (`GET /devices`).
- Provides detailed drive-level metrics for a device (`GET /devices/{device_id}`).
- Lightweight health check (`GET /health`).
- Simple HTML view that mirrors the CLI summary (`GET /stats`).
- Automatically reloads data whenever `engagement_db.json` changes.
- Optionally pulls new per-drive records from an authenticated cursor API.
- Google sign-in with an owner-managed list of approved account emails.
- Revocable guest links expiring exactly 24 hours after creation.

## Private access and Google sign-in

All dashboards, data endpoints, and API documentation require authentication by
default. `/health` remains public and returns only the service status. If Google
credentials are missing, private data stays blocked and the login page explains
that access is being set up. The background drive-stat synchronizer is unaffected.

Google Cloud setup is done **once for the website**, not once per person:

1. Select or create a project in [Google Cloud Console](https://console.cloud.google.com/).
2. Open **Google Auth Platform → Branding** and set the app name and contact email.
3. Set **Audience** to **External**. This app requests only `openid email`;
   Google exempts these basic identity scopes from the test-user restriction, even
   while the app is in Testing. No Gmail mailbox permissions are requested.
4. Under **Clients**, create a **Web application** client. Add the exact
   authorized redirect URI `https://openpilotstats.duckdns.org/auth/callback`
   (or replace the origin with your site's HTTPS origin).
5. Copy `server/web_auth.json.example` to `.web_auth.json` in the project root.
   Set `owner_email`, `client_id`, and `client_secret`. Generate a session secret
   using `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'` and put it
   in `secret`. Protect the file with `chmod 600 .web_auth.json`.
6. Install `server/requirements.txt` in the service's virtual environment, then
   restart the service. Sign in as the owner and open **Manage access** from the
   home page, or visit `/access` directly.

Google references: [OpenID Connect setup](https://developers.google.com/identity/openid-connect/openid-connect)
and [basic sign-in scopes and the Testing exception](https://support.google.com/cloud/answer/15549945?hl=en).

On the access page, enter someone's Google account email to allow ongoing viewer
access. They simply click **Sign in with Google** using that account; they do not
create any Google Cloud project or credentials. Only the owner manages users and
links. Removing an account ends its active sessions on their next request.

Alternatively, create a **24-hour guest link** and copy it to share. Anyone holding
the link can view all dashboards and their JSON data without signing in. The
expiry is measured from creation, not first use; active guest sessions stop at
that same deadline. **Revoke** immediately ends the link and associated guest
sessions on their next request. Tokens are stored as hashes in SQLite, survive
service restarts, and are shown only once when created. Opening a link redirects
to a clean URL and creates a Secure, HttpOnly cookie. Google sessions have an
absolute seven-day lifetime before another sign-in is required.

`.web_auth.json` and `.web_auth.sqlite3*` are ignored by Git. Keep the JSON session
secret stable across restarts and include both files in private backups. The
default SQLite path is in the project root so deploying the `server/` directory
does not replace access records. The app never includes Google access tokens in
the browser session. Serve through HTTPS and keep uvicorn on loopback.

Configuration can also come from `WEB_AUTH_CONFIG_FILE` or override fields with
`WEB_AUTH_PUBLIC_URL`, `WEB_AUTH_OWNER_EMAIL`, `WEB_AUTH_SECRET`,
`WEB_AUTH_CLIENT_ID`, `WEB_AUTH_CLIENT_SECRET`, and `WEB_AUTH_DATABASE`.
For deliberate local-only development without the gate, set `WEB_AUTH_ENABLED=0`.
To check the security and data tests, run:

```bash
.venv/bin/python -m unittest discover -s server -p 'test_*.py'
```

## Prerequisites

- Python 3.10+ (Ubuntu 24.04 ships with Python 3.12).
- The `engagement_db.json` file generated by `engagement_gauge_dev.py`.

## Quick Start

```bash
# 1. Copy the project to the VPS (or clone from git after you push it)
scp -r engagement_gauge_dev oracle:~/engagement_gauge_dev

# 2. SSH into the VPS
ssh oracle
cd ~/engagement_gauge_dev

# 3. Create a Python virtual environment
python3 -m venv .venv
source .venv/bin/activate

# 4. Install the API dependencies
pip install --upgrade pip
pip install -r server/requirements.txt

# 5. Run the API (default port 8000)
uvicorn server.app:app --host 0.0.0.0 --port 8000
```

The API uses the `engagement_db.json` file located at the project root by default. To point at a different file, set the `ENGAGEMENT_DB_PATH` environment variable before launching uvicorn:

```bash
export ENGAGEMENT_DB_PATH=/home/oracle/data/engagement_db.json
uvicorn server.app:app --host 0.0.0.0 --port 8000
```

## Automatic drive-stat synchronization

Set `DRIVE_STATS_SOURCE_URL` and provide the scoped source token to enable the
background puller. It runs immediately at startup and polls every 60 seconds.
Fetched records are upserted by `(device_id, drive)`, the JSON database is
replaced atomically, and the cursor advances only after the data is durable.
Schema v4 records also include blinker-derived non-intersection disengagements.
The device, comparison, and total summaries show their counts and rates. Rates
use only drives carrying the new metric; older drives remain in other totals.
Detection means no single blinker was observed from eight seconds before to
three seconds after a disengagement, with the final manual shutdown excluded.

```bash
export DRIVE_STATS_SOURCE_URL='https://goranconnect.duckdns.org/api/drive-stats/export'
printf '%s\n' '<scoped token>' > .drive_stats_source_token
chmod 600 .drive_stats_source_token
uvicorn server.app:app --host 0.0.0.0 --port 8000
```

The token can instead be supplied through `DRIVE_STATS_SOURCE_TOKEN` or a
custom `DRIVE_STATS_SOURCE_TOKEN_FILE`. Optional settings are:

- `DRIVE_STATS_POLL_INTERVAL` (default `60` seconds)
- `DRIVE_STATS_PAGE_SIZE` (default `100`, maximum `500`)
- `DRIVE_STATS_SOURCE_TIMEOUT` (default `30` seconds)
- `DRIVE_STATS_CURSOR_PATH` and `DRIVE_STATS_LOCK_PATH`

The cursor, lock, and default token files are ignored by Git. Existing entries
in `engagement_db.json` are retained, so this replaces the old SSH file-copy
workflow without discarding historical statistics.

## Optional: systemd Service

Create a unit file (e.g. `/etc/systemd/system/engagement-gauge.service`):

```
[Unit]
Description=Engagement Gauge API
After=network.target

[Service]
User=oracle
Group=oracle
WorkingDirectory=/home/oracle/engagement_gauge_dev
Environment="ENGAGEMENT_DB_PATH=/home/oracle/engagement_gauge_dev/engagement_db.json"
ExecStart=/home/oracle/engagement_gauge_dev/.venv/bin/uvicorn server.app:app --host 0.0.0.0 --port 8000
Restart=always

[Install]
WantedBy=multi-user.target
```

Reload systemd and enable the service:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now engagement-gauge.service
```

## Nginx Reverse Proxy with DuckDNS + HTTPS

1. **Create the DuckDNS record** – point `<subdomain>.duckdns.org` to your VPS public IP in the DuckDNS dashboard.
2. **Install Nginx and Certbot**:

   ```bash
   sudo apt update
   sudo apt install nginx
   sudo apt install certbot python3-certbot-nginx
   ```

3. **Open firewall/security ports** – allow inbound TCP 80/443 using UFW and the Oracle security list:

   ```bash
   sudo ufw allow 'Nginx Full'
   sudo ufw delete allow 'Nginx HTTP'  # optional cleanup if present
   ```

4. **Create an Nginx site** using the sample in `server/nginx.conf.example`, replacing the placeholder domain:

   ```bash
   sudo cp server/nginx.conf.example /etc/nginx/sites-available/engagement-gauge
   sudo ln -s /etc/nginx/sites-available/engagement-gauge /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl reload nginx
   ```

5. **Obtain HTTPS certificates with Certbot**:

   ```bash
   sudo certbot --nginx -d <subdomain>.duckdns.org
   ```

   Certbot updates the Nginx config to terminate TLS on port 443 and configures automatic renewal (`/etc/cron.d/certbot`). Test renewal with `sudo certbot renew --dry-run`.

6. **Run uvicorn behind Nginx** – keep the FastAPI service bound to `127.0.0.1:8000` (systemd unit above already does this). Nginx proxies incoming HTTPS traffic to the local service.

After these steps your API is reachable at `https://<subdomain>.duckdns.org`, with Nginx handling TLS and forwarding requests while your FastAPI app stays on the internal loopback port.

## Security Notes

- Keep private access enabled when exposing the site publicly.
- Use HTTPS via the reverse proxy for Google callbacks and Secure session cookies.
